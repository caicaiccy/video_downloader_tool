# Chrome / Edge 视频本地下载器（扩展 1.5.2）

Manifest V3，支持 Bilibili 页面、通用公开视频页面及浏览器已提供的媒体资源。使用 activeTab、scripting、storage、nativeMessaging；HTTP(S) 域名权限仅列为可选，不默认授权全站。

## 安装与升级

1. 解压完整平台包。在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 启用开发者模式，加载包内 `browser-extension` 文件夹。已加载此源码文件夹时，更新文件后重新加载扩展。
2. 复制各浏览器的扩展 ID。安装或升级本机 Host（仅更新扩展不能获得新功能）：
   - Windows PowerShell：`./install_native_host_windows.ps1 -HostPath ./BiliDownloaderHost.exe -ChromeExtensionId <Chrome扩展ID> -EdgeExtensionId <Edge扩展ID>`
   - macOS：`sh ./install_native_host_macos.sh /绝对路径/BiliDownloaderHost <Chrome扩展ID> <Edge扩展ID>`
3. 仅用一个浏览器时只填写对应 ID；Edge-only macOS 安装用空的 Chrome 参数 `""`。源码中的脚本位于 `scripts/`，Host 构建后位于 `dist/host/`。
4. 重新加载扩展。Host 名称保持 `com.codex.bili_downloader`，无需新增注册项。旧 Bilibili 队列兼容；通用任务要求 Host 的 `public_web_media` 能力声明。

## 使用

逐行粘贴 HTTP(S) 网页链接，点击“加入列表”并“开始队列”，Host 独立解析网页及嵌入播放器，扩展后台读取媒体后交给 Host 下载合并。不创建网站页签，不依赖当前标签页。HTML video/source、VideoObject 结构化信息、播放器公开的 HLS/DASH 清单及简单源地址赋值均可解析；多个同优先级资源会提示扫描选择。解析成功后队列更新为视频标题。Bilibili 保留原有专用解析器，同样直接输入链接即可。

下载中新增的链接会在当前批次结束后自动进入下一批次，不会停留在“等待中”。若队列启动失败，错误会直接显示在对应任务中，可修复后使用“重试失败项”。

网页后台下载需要 Host 1.5.1 / page_scan / background_http 能力，Chrome 需保持运行。此方式不打开网站、不执行页面 JS，每页最大 2 MB，最多 8 个页面、嵌套 3 层。所选线路只有不透明运行时令牌时，会尝试网页明确列出的同集备用线路，寻找公开 HLS/DASH 地址。扩展后台先尝试正常 CORS fetch(credentials=omit)，已允许的媒体不申请额外权限；若请求失败且域名未授权，任务提供“授权视频来源并继续下载”，授权指定域名后重试。服务端 401/403 仍按真实响应报错，不用权限提示覆盖。所有线路都必须执行私有代码才能产生地址时，仍需原播放器扫描。

动态或跨站播放器：正常打开并播放目标视频，打开弹窗即可自动扫描一次，零结果隐藏；右上角图标可手动重扫，悬停提示“扫描媒体”。自动扫描只使用已有权限，不弹出授权请求。若提示待授权域名，点“授权并扫描跨站播放器”并完成浏览器授权，再选择 HLS、DASH 或直链资源并加入队列。新扫描任务显示“浏览器 · HLS”等标签；若已有同 URL 的失败任务，点击加入会刷新该任务并清空旧错误。嵌套 iframe 可能需要再次授权下一级播放器域名。授权由浏览器保存，可在扩展网站权限中撤销。

扫描只读当前可访问帧中的 video/source、资源时序及公开内联脚本 URL，DIRECT 地址不从脚本字面值单独推断，避免广告/占位视频误报；HLS/DASH 脚本清单仍可作为 blob 播放器的候选。扫描选项与入队任务使用相同标题，不执行脚本、不读取播放器私有状态、不解密地址、不抓取 Cookie。blob: 是播放句柄，必须找到底层 HTTP(S) 地址；发现 EME mediaKeys 时不提供候选。无扩展名的网络清单、封闭 Shadow DOM、动态 worker 中隐藏地址等不一定能识别。

默认保存到系统下载目录，右上角“设置”打开独立设置页，左上角箭头返回下载页。在设置页点击“更改”通过系统文件选择器选择并记住文件夹；“恢复默认”恢复下载目录，文件夹图标通过访达/资源管理器打开当前目录。运行中的队列使用启动时的目录，队列结束后才能更改。

队列按下载中、待下载、失败、完成排序，同类按加入时间从晚到早；待下载任务也按此顺序执行。旧任务没有时间字段时按原列表倒序。最多显示 5 条，更多可滚动。输入链接和加入队列区域位于队列下方，输入框默认一行，自动增高到最多 5.5 行，超出可滚动。重试次数在设置页调整并自动保存，默认重试 3 次（上限 5），支持取消和重试失败项。访问限制、DRM、加密或不支持的协议不自动重试。失败详情和输出路径显示在任务下面，悬停可查看完整内容。过期资源请重新扫描并加入。

完成任务显示录像机图标（悬停提示“播放视频”），使用系统默认播放器打开。Ctrl + 点击为本次播放选择其他应用，不改变默认关联。无默认播放器时，macOS 提供选择并设为默认流程，Windows 打开系统默认应用设置并提供应用选择窗口。文件已移动/删除时提示错误。目录设置和播放需要 Host 的 desktop_actions 能力。

仅保存你有权保存的公开视频。扫描任务在原播放器帧使用浏览器 fetch(credentials=omit) 匿名读取，以有序小块传给 Host，Host 检查加密/DRM 并用 FFmpeg 合并；这类任务需要保持原页面打开。手动网页链接无需播放器页，媒体由后台 fetch 读取。浏览器正常播放不代表匿名 fetch 可访问。403 / 401、登录、会员、验证码或地区限制会停止；不导出凭据、切换代理或绕过限制。HLS AES-128 / SAMPLE-AES、DASH ContentProtection 也拒绝；暂不支持直播。

## 故障排除

- 找不到 Host：运行完整包中的安装脚本；仅扩展 ZIP 不含下载引擎。
- ID 未授权：使用当前浏览器详情页显示的 ID 重新注册；Chrome 和 Edge ID 可不同。
- Host 过旧：用最新完整包重新运行安装器，它会复制新版可执行文件到原目录。
- 30 秒未就绪：检查 Host 路径、系统首次启动提示和 ID。扩展先等待 Host 就绪，再提交队列。
- 旧任务显示“本机 · HLS”并报 403：更新 Host 和扩展后，重新扫描并选择同一媒体加入，会将旧失败任务更新为浏览器传输。
- 新任务仍报 403 / CORS / 匿名请求失败：资源仍拒绝访问，任务停止；不导出凭据、不伪造 Origin/Referer、不改代理绕过限制。
