# 弹窗便利性更新与验证

## 行为

- 默认目录为系统下载目录，使用系统文件选择器更改，保存后跨弹窗/浏览器重启保留。可以恢复默认，或通过访达/资源管理器打开当前目录。队列启动时固定目的目录，下载期间不可修改。
- 打开弹窗自动扫描一次，零候选隐藏结果；跨站授权按钮独立显示，自动扫描不申请新权限。手动扫描移到右上角图标，标题和无障碍名称为“扫描媒体”。
- 页脚仅保留“下载时请保持播放器页面打开。”；任务不再显示尝试次数。完成任务提供播放按钮，默认调用系统关联应用；Ctrl 点击为单次播放选择其他应用。macOS 无默认应用时选择并设为默认，Windows 使用系统默认应用设置与打开方式窗口。
- 下载中（含重试等待）、待下载（含取消后可继续的任务）、失败、完成依次排列，同类按加入时间倒序。没有时间字段的旧任务使用原列表倒序，新增任务记录毫秒时间。待下载任务执行顺序与显示顺序一致。
- 队列每条 64 px，最多显示 5 条，列表超过 320 px 即可滚动。链接输入与添加区域移到队列下方。

## 验证

20 项 Python 测试、Node 扩展测试通过。包括目录选择保存/取消/恢复、队列使用所选目录、视频不存在/非视频路径拒绝、默认播放器和应用选择的不同分支、无默认播放器设置与取消、Native Messaging 操作响应、队列运行时修改目录拒绝；保留原有真实 MP4/HLS/DASH 下载和解码回归。扩展测试覆盖自动扫描一次、零结果隐藏、不自动申请域名权限、Ctrl 修饰键传递、排序与执行顺序、不显示次数、仅允许弹窗发起本地操作、从已完成任务读取文件路径而非任意请求路径。

macOS arm64 完整包构建通过。已注册 Host 返回 1.3.0、协议 4、desktop_actions，并通过真实消息帧返回 `/Users/admin/Downloads`。窗口操作在单独进程中执行，不阻塞主 Host 的媒体响应。目录偏好独立保存到应用设置；扩展仅缓存路径，设置和下载都以 Host 的偏好为准。

本地布局测试使用 7 条模拟任务：列表高度 320 px，内容高度 448 px；滚动后 scrollTop=128，剩余完成任务可见。截图为 `popup-five-jobs-preview.png`，仅用作布局验证，不代表实际下载记录。

Windows 系统分支通过模拟 API 验证，未在 Windows 实机验收。无默认播放器分支采用模拟验证，未修改本机现有文件关联。

本机系统操作实测：打包后的目录选择器成功返回所选目录，测试不保存偏好；打开目录返回成功，访达窗口标题为“下载”；默认播放返回成功，QuickTime 显示既有 Agedm 视频文件及 24:00 时长，截图为 `default-player-verified.png`。Chrome 实际新弹窗仍需用户重新加载后验收；此前安全策略禁止自动操作扩展管理页，未通过其他方式执行重新加载。


添加反馈的最终位置：扫描媒体、当前页面和手动链接均在原按钮上短暂显示绿色成功提示，2.5 秒后恢复按钮文字；重复资源显示“已在队列中”，刷新旧失败媒体显示“队列已更新”。删除队列下方的 currentLinkFeedback 和底部长段浏览器媒体说明。空闲时底部状态区隐藏，仅保留“下载时请保持播放器页面打开。”；队列消息独立保存在 queueMessage，旧 lastMessage 中的添加提示不再显示，下载进度和队列启动/结束/错误仍保留。其他操作错误在标题下方提示，不覆盖队列进度。
