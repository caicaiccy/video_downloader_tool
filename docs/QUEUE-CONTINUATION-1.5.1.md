# 队列续接修复 1.5.1

## 现象与原因

复现记录中，网页链接任务在上一项仍下载时加入。Native Host 处理的是“开始队列”时收到的任务快照，旧扩展在该批次完成后没有再次读取等待项，导致中途加入的任务永久显示“等待中”。已完成的视频文件和扩展存储时间共同确认了这个时序。

## 修复

- 正常批次完成后重新读取扩展队列，自动开始运行期间新增的等待项。
- 为续接的普通网页链接补全后台媒体传输标记；Bilibili 与已扫描媒体保持原有路径。
- 用户取消队列时不自动续接。
- 需要媒体域名授权的任务等待用户明确授权，不进行循环重试。
- 队列无法启动时，将具体错误写入相应任务并标记为失败，避免继续显示“等待中”。
- 所选线路只公开不透明运行时令牌时，读取网页列出的同集备用线路；找到公开 HLS/DASH 即使用后台传输，不执行私有播放器代码。

## 验证

- 扩展集成测试模拟第一批下载期间加入网页链接，确认 `queue_done` 后自动发送第二批，并确认 `transport=background`。
- 扩展集成测试模拟 Native Host 启动失败，确认任务变为“失败”且保存具体原因。
- 后台传输测试覆盖权限、分块回压、取消及资源清理。
- 28 项 Python 测试覆盖 MP4、HLS、DASH、同集备用线路、网页解析、浏览器转发、合并、完整解码和访问限制策略，全部通过。
